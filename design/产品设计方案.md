# 校园活动与机会平台 · 产品设计方案

| 项目 | 内容 |
| --- | --- |
| 文档版本 | **v4.0（轻量版）** |
| 对应需求 | 同目录 `产品设计思路.txt` |
| 数据依据 | 同目录 `已知校园活动汇总.md`（26 条，编号 01–26） |
| 结构化种子数据 | 同目录 `activities.seed.json` |
| 产品形态 | **本地运行的轻量 Web 站**（Win11 + Edge，单进程） |
| 运行要求 | Node ≥ 22（本机已验证 v24.19.0）；无需 Docker / npm install / 构建 |

## v4.0 修订说明：一次减法

v3.0 的设计重量与数据规模严重不匹配——424 行设计、24 张表、21 个接口、10 个页面、4 张数据表，对应的是 **26 条活动、54KB JSON**。技术栈要求 Docker + PostgreSQL + Redis + MinIO + LibreOffice + ClamAV，而部署目标已从"校内服务器"变成"Win11 本机"。本版按"轻量化"目标做了一次彻底减法。

| 项目 | v3.0 | v4.0 |
| --- | --- | --- |
| 技术栈 | Next.js + NestJS + PostgreSQL + Redis + MinIO + LibreOffice 容器 + ClamAV + Docker | **单进程 Node（零依赖）+ JSON 文件 + 原生 HTML/JS** |
| 文档转换 | 服务端 LibreOffice 转 PDF + 队列 | **全部在浏览器端完成**，服务端零转换 |
| 附件预览 PDF | PDF.js | **Edge 内置 PDF 阅读器** |
| 数据存储 | PostgreSQL + Prisma + 对象存储 | **JSON 文件**（升级路径：`node:sqlite`，本机已验证可用） |
| 补充权限 | 账号体系 + 四层可信度分级 + 认领审核 + 审计后台 | **每活动一个补充口令**，无需注册登录 |
| 部署 | Docker Compose | **双击 `start.bat`** |
| 规模 | 424 行 / 24 表 / 21 接口 / 10 页面 | 约 200 行 / 6 接口 / 3 页面 |

**砍掉的功能（第一阶段明确不做）**：账号与登录、校园认证、组织者认领、审核队列、审计后台、报名/候补/签到、组队找搭子、往届评价口碑、课表 `.ics` 冲突检测、新生三步引导与个性化排序、多模块管理后台、信息完整度评分、地图导航与"步行 N 分钟"、服务端文档转换、对象存储、病毒扫描服务、Docker。

## 1. 定位（承诺调整）

v3.0 的定位是"让新生在三分钟内判断这个活动值不值得去"。**这个承诺超出数据能支撑的范围**：26 条里收获（学分/工时/证书）**0 条**、费用金额 **0 条**、地点仅 **15%**，决策卡最关键的两行会永久显示"未收录"。与其把承诺挂在数据给不出的答案上，不如把承诺降到数据能支撑的程度：

> **把 26 条校园活动摊开成卡片，让你一眼看清门槛、地点、时间、截止和报名方式；缺什么，也明确告诉你。**

这仍然直接服务于原始需求里的"帮助学生辨别活动是否值得参与"——只是把"值不值得"拆成可回答的部分（能不能去、在哪、什么时候、要不要报名），并把无法回答的部分（收获、费用）**如实标为"未注明"**，而不是留空或编造。

## 2. 功能范围

### 2.1 第一阶段做（全部内容）

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | **活动卡片墙** | 26 条活动以卡片展示，含状态与关键字段，无需分页 |
| 2 | **筛选与搜索** | 按门槛（零基础/需基础）、类型、报名状态、关键词 |
| 3 | **活动详情页** | 完整字段 + 附件列表 + 变更记录 |
| 4 | **补充口令编辑** | 组织者凭专属链接补充/修正信息、上传附件，无需注册 |
| 5 | **附件在线预览** | 图片 / PDF / txt / md / docx 浏览器端渲染 |
| 6 | **变更留痕** | 字段级历史：谁在什么时候把什么从什么改成了什么 |

### 2.2 明确不做（第一阶段）

见上方"砍掉的功能"。其中两点需要特别说明：

- **报名**：不做报名系统，但 `signup_mode` 字段作为**信息展示**保留（如"无需报名，直接前往""需在 9月24日 22:00 前报名"）。这正是数据的真实形态——26 条里有 6 条根本无需报名，为一个不需要报名的活动做报名功能没有意义。
- **信息完整度评分**：删除 5 项评分。因为费用 0 条有金额、收获 0 条，**满分不可达**，评分会全部挤在 2/5 而失去区分度。改为在每个字段处直接标"未注明"——信息量相同，实现成本为零。

**设计要点**

- **每张卡只放 4–5 个字段**，取最能决定"去不去"的：时间、地点、门槛、截止、报名方式。不堆砌。
- **状态徽章**放右上角：报名中 / 报名已截止 / 已结束 / 长期 / 地点待定。已结束与报名已截止默认不展示（可筛出）。
- **"未注明"直接写在字段位置**（如 `地点  未注明`），不留空、也不用评分替代。
- **变更提示**：有补充修改过的活动显示一行 `⚠ 时间与地点已变更，见详情`。
- 整卡可点击进详情；右下角"我是组织者"是**弱化文字链**，不抢主任务（学生浏览）的注意力。点击后进入口令验证。

## 4. 补充口令机制

**问题**：v3.0 用"四层可信度分级 + 认领审核 + 审计后台"来保证补充信息可信，这是整个系统最重的部分，而 26 条里有 **20 条未注明发布方**，没有明确对象可以邀约认证——机制很可能空转。

**方案**：每张活动一个**专属补充口令**，无需注册登录。

| 项目 | 设计 |
| --- | --- |
| 口令生成 | `crypto.randomBytes(12).toString('hex')`，24 位十六进制（本机已验证可用） |
| 使用方式 | 链接 `http://localhost:3000/edit/<token>`，点开即可编辑 |
| 发放方式 | 从 `data/activities.json` 取出对应口令，直接发给该活动的组织者（26 条，手工发一遍即可） |
| 泄露处理 | 重新生成口令，旧链接立即失效 |
| 安全边界 | 口令即凭证，无账号体系；本地运行、无公网暴露时风险可接受 |
| 是否需要审核 | **不需要**。但**必须留痕**（见下） |

**唯一保留的信任机制：编辑直接生效，但全部留痕。** 每个字段被修改时记录 `{字段, 原值, 新值, 时间, 来源}`，详情页展示"更新记录"，字段被改过就同时显示原值。这样即使误改或恶意修改也可追溯、可回滚，而实现成本仅仅是多写一个 `history.json`。

> 这是本次减法的关键判断：**去掉审核流程，保留留痕**。审核需要人力与队列，留痕只需要一个数组。

## 5. 附件在线预览

全部在**浏览器端**完成，服务端不做任何转换——这是删掉 LibreOffice、Redis、队列的直接原因。

| 格式 | 预览方案 | 说明 |
| --- | --- | --- |
| `.png` `.jpg` `.webp` `.gif` | 直接显示 | — |
| `.pdf` | **Edge 内置 PDF 阅读器**（`<iframe src>`） | 省掉 PDF.js；Win11 Edge 原生支持 |
| `.txt` | `TextDecoder` 自动识别 **UTF-8 / GBK** | 本机已验证：`new TextDecoder('gbk')` 正确解码中文，无需服务端探测 |
| `.md` | 前端极简 Markdown 渲染 | 26 条数据用不到完整解析器，自写或本地引入轻量库 |
| `.docx` | **mammoth.js 浏览器端转 HTML** | 本地存放（`public/vendor/`），离线可用；版式有损失但内容完整可读 |
| `.pptx` | **不渲染**，提示上传 PDF 版本 + 提供原件下载 | PPT 无轻量浏览器端渲染方案；引导上传者导出 PDF（导出后即可用 Edge 预览） |

**上传**：`POST` multipart → 存到 `data/uploads/<活动编号>/`，保留原文件名。
**安全**：只做三件事——扩展名白名单、**magic number 校验**（防改扩展名）、单文件大小上限（建议 20MB）。不做 ClamAV（签名库太重，本地单人使用场景收益极低）。

## 6. 技术方案

### 6.1 架构

**一个 Node 进程，零 npm 依赖，零构建。** 已在本机（Node v24.19.0）验证以下内置能力全部可用：

- `node:http` —— 静态文件服务 + 极小 JSON API
- `node:crypto` —— 口令生成
- `node:sqlite` —— 无需 flag 即可用（当前为升级路径，MVP 不用）
- `TextDecoder('gbk')` —— 中文 txt 预览

### 6.2 目录结构

```text
school/
├── server.js                  # 唯一服务端文件（静态服务 + 6 个接口）
├── start.bat                  # 双击启动：起服务 + 打开 Edge
├── data/
│   ├── activities.json        # 运行时数据（首次由种子数据生成，之后被补充编辑）
│   ├── history.json           # 字段级变更记录
│   └── uploads/               # 上传的附件
├── public/
│   ├── index.html             # 卡片墙
│   ├── activity.html          # 详情页
│   ├── edit.html              # 补充/编辑页
│   ├── app.js  style.css
│   └── vendor/                # mammoth.js 等本地库（离线可用）
└── design/                    # 设计与数据（现有，不变）
    ├── 产品设计思路.txt
    ├── 已知校园活动汇总.md
    ├── 产品设计方案.md          # 本文档
    └── activities.seed.json   # 原始结构化种子数据（只读导入源）
```

### 6.3 数据存储

- **MVP 用 JSON 文件**：26 条数据、单进程运行，不存在并发写问题；写入采用"临时文件 + 重命名"保证原子性。
- `design/activities.seed.json` 是**只读导入源**；`data/activities.json` 是运行时数据。两者分离，便于随时重新导入。
- **升级路径**：若日后需要多用户并发或数据量增长，换 `node:sqlite`（本机已验证可用，无需 flag），届时只需替换数据访问层。

### 6.4 接口（共 6 个）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/activities` | 卡片墙数据（支持筛选参数） |
| `GET` | `/api/activities/:id` | 详情 + 附件列表 + 变更记录 |
| `GET` | `/api/activities/:id/verify?token=` | 校验补充口令 |
| `PUT` | `/api/activities/:id?token=` | 保存补充/修正，写入变更记录 |
| `POST` | `/api/activities/:id/files?token=` | 上传附件 |
| `GET` | `/files/:id/:name` | 读取附件 |

### 6.5 启动方式

```bat
:: start.bat
node server.js
start msedge http://localhost:3000
```

**运行前提**：本机已装 Node ≥ 22（当前 v24.19.0）。无 Docker、无 `npm install`、无构建步骤、无外部服务、无网络依赖。

## 7. 数据现实与数据字典

### 7.1 字段覆盖率（26 条实测）

数字由 `activities.seed.json` 的 `_meta.coverage` 直接统计（分母 26）：

| 字段 | 有效条数 | 覆盖率 |
| --- | --- | --- |
| 具体时间 | 16 | 62% |
| 参与门槛/要求（含非硬性偏好） | 15 | 58% |
| 投入要求 | 15 | 58% |
| 面向人群/资格限制 | 12 | 46% |
| 报名截止（有具体日期） | 8 | 31% |
| **线下明确地点** | **4** | **15%** |
| 名额限制 | 5 | 19% |
| 费用（提及，但均无金额） | 2 | 8% |
| **收获（学分/工时/证书）** | **0** | **0%** |

地点分布：明确 4 条（02、09、10、21）· 线上 2 条（04、17）· 待确认 2 条（22、23）· **未注明 18 条**。

**这三个数字划定了产品承诺的边界**：地点 15% → 卡片上会大量出现"未注明"；收获 0%、费用金额 0 → 无法回答"能拿到什么"，因此定位不承诺"值不值得"（见第 1 章）。同时这也说明**补充机制值得保留**：那 18 条缺失地点的活动正是它的服务对象。

### 7.2 数据源中的信息陷阱与处理

| 陷阱 | 数据实例 | 处理 |
| --- | --- | --- |
| 同一活动重复/增量发布 | 01 ↔ 09、03 ↔ 20 | 补充通知不单独成卡，合并为父活动的变更记录 |
| 时效已过 | 04（直播已结束）、19（报名已截止）、17（网盘链接 9/22 失效） | 状态标注，列表默认过滤 |
| 信息不完整 | 12（费用未提供）、16（截止未注明）、22/23（地点未定）、24/25（无主办方无地点） | 字段处直接标注"未注明" |
| 疑似营销/风险 | 24（"零门槛、日结"，要求加私人微信）、25（标题技术交流、正文购买链接） | 按 `risk_level` 标注警示 |
| 无需报名 / 非先到先得 | 02、04、10、15、21、26（无需报名）；14（报名≠录取） | 报名方式**仅作信息展示**，因此不做报名系统 |
| 非活动类信息 | 17（Python 资料合集） | 分类为"资料/资源"，不套用活动字段 |

### 7.3 数据字典

运行时字段来自 `activities.seed.json`，枚举已规范化（详见该文件 `_meta.enums`）：

| 字段 | 含义 | 取值 |
| --- | --- | --- |
| `id` | 编号 | `01`–`26` |
| `name` | 活动名称 | — |
| `audience` | 面向人群 | 全校学生 / 大一新生 / 仅限大二及以上 / null |
| `threshold` | 参与门槛 | 零基础可参加 / 需提交自我介绍 / 需组队 / null |
| `commitment` | 投入要求 | 每周约 5 小时 / 共 6 周 / null |
| `location` + `location_status` | 地点与状态 | 明确 / 线上 / 待确认 / 未注明 |
| `schedule` | 时间 | — |
| `deadline` + `deadline_status` | 报名截止与状态 | 明确 / 已截止 / 长期 / 未注明 / 无需报名 / 继承父活动 |

## 8. 与原始需求的关系

| 原始要求 | 第一阶段是否满足 | 说明 |
| --- | --- | --- |
| 组织者发布活动信息，支持 PPT/Word/图片/txt/md | ✅ | 通过补充口令页面上传；浏览器端预览；PPT 需同时上传 PDF |
| 在线浏览活动资料 | ✅ | 卡片墙 + 详情页 + 附件预览 |
| 帮助辨别活动是否值得参与 | ⚠️ 部分 | 门槛/地点/时间/截止/报名方式可判断；**收获与费用数据源缺失，如实标"未注明"** |
| 学生自主发布活动、招募伙伴 | ❌ 不做 | 固定 26 条，无新增活动入口、无招募功能。新增活动只需手动往 `activities.json` 加一条记录，无需开发 |
| 多来源信息可能产生的问题 | ✅ | 以「活动」为单位合并（09/20）；过期默认过滤；风险条目（24/25）标注警示 |
