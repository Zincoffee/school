## 1. 需求解读

### 1.1 原始要求拆解

| 原文要求 | 本质问题 | 难度 |
| --- | --- | --- |
| 组织者发布活动信息，支持 PPT/Word/图片/txt/md | 富格式内容的**上传与在线浏览** | 中（格式转换是主要成本） |
| 在线浏览活动资料 | 让用户不下载就能看懂 | 中 |
| 帮助辨别活动是否值得参与 | **决策支持** | 高（产品设计难点） |
| 学生自主发布活动、招募伙伴 | 供给侧开放 | 中高 |
| 多来源信息可能产生的问题 | 真实性、重复、过期、营销噪声 | 高 |

**「最基本功能：发布信息」是入口，「判断」是价值，「多来源治理」是生死线。**

### 1.2 三个用户角色

| 角色 | 核心诉求 | 关键痛点 |
| --- | --- | --- |
| **新生**（重点） | 这活动是什么、我能去吗、在哪、值不值得去 | 不知道门槛、找不到地点、怕白跑、怕被骗 |
| 普通学生 | 快速找到对口机会与同伴 | 信息散落群聊/公众号，过期信息干扰 |
| 组织者（学院/社团/学生个人） | 低成本发布，招到人 | 触达差、报名统计靠问卷、资料无人看 |

## 2. 产品定位与设计原则

> **一句话定位**：一个让新生在三分钟内判断"这个活动值不值得去"、并且只发布可信活动的校园机会平台。

**六条设计原则**

1. **决策优先**：任何页面先回答"值不值得"，再展示"是什么"。
2. **白名单守门**：只能发布活动库中已收录的活动，从源头消除虚假信息。
3. **平台标注优先于发布者资料**：平台标注是可信基准，发布者上传的资料是补充材料，两者在视觉与文案上必须可区分。
4. **"未注明" ≠ "没有"**：信息缺失必须显式显示为"未注明"，而不是留空。缺失本身就是判断依据（没有主办方、没有地点的活动，风险信号极强）。
5. **过期即归档**：活动结束/报名截止后自动降级，默认从列表移除。
6. **新生默认友好**：首次进入不做空列表，给引导 + 现成的"新生友好"内容。

## 3. 数据基础分析

本节是对 `已知校园活动汇总.md` 的实际分析，v2.0 的所有机制都由此推导。

### 3.1 文件实际结构

文档为**三列表格**，共 26 条：

| 编号 | 信息 | 主要内容 |
| --- | --- | --- |
| 01 | “蓝桥杯”程序设计校内训练营 | 9月24日22:00报名截止；原计划9月20日起每周六19:00训练；面向全校学生；零基础可参加 |
| 09 | 程序设计训练营补充通知 | 因场地调整，首次训练改为9月21日19:30，地点改至实验楼A402；已报名同学无需重复提交；报名截止时间不变 |

**关键观察：表格没有独立的「要求」列和「地点」列。** 时间、截止、地点、面向人群、门槛、名额、费用全部混在「主要内容」这一整句散文里。因此"在文件下方注明要求和地点"这件事，**前提是把散文拆成结构化字段**——这是本方案的核心工作项，详见第 5 章。

### 3.2 字段覆盖率（26 条实测）

下表数字**由 `activities.seed.json` 直接统计**（分母 26），与该数据文件 `_meta.coverage` 完全一致：

| 字段 | 有效条数 | 覆盖率 |
| --- | --- | --- |
| 具体时间 | 16 | 62% |
| 参与门槛/要求（含非硬性偏好） | 15 | 58% |
| 投入要求 | 15 | 58% |
| 面向人群/资格限制 | 12 | 46% |
| 报名截止（有具体日期） | 8 | 31% |
| **线下明确地点** | **4** | **15%** |
| 名额限制 | 5 | 19% |
| 费用（提及，但均无金额） | 2 | 8% |
| **收获（学分/工时/证书）** | **0** | **0%** |

**地点字段的完整分布**（这是本次评审最关键的发现）：

| 地点状态 | 条数 | 条目 |
| --- | --- | --- |
| 明确（线下） | 4 | 02、09、10、21 |
| 线上（无需地点） | 2 | 04、17 |
| 待确认 | 2 | 22、23 |
| **未注明** | **18** | 其余全部 |

**三个必须写进方案结论的发现：**

1. **"注明要求和地点"方向是对的，但地点只有 15% 覆盖率。** 26 条里仅 4 条有可用的线下地点，另有 2 条是线上活动（无地点问题）、2 条明确写了待确认，**其余 18 条根本没提地点**。所以标注机制上线后，**它最主要的产出不是"地点"，而是把"地点未注明"这个信息缺口显式暴露出来。**
2. **收获字段 0 条**：没有任何一条提到学分、工时或证书。这意味着决策卡的"收获"行会长期显示"未收录"。这不代表活动没价值，但**产品不能编造，也不应留空**。
3. **费用字段只统计到 2 条，且两条都没有金额**（12 为"未提供"、22 为"AA"）。所以"已知具体费用金额"实为 **0 条**——费用是参赛/参与决策的关键项，这是比地点更严重的缺口。

**因此标注机制必须配补录通道**（发布者补充 + 平台审核入库），否则这两项覆盖率永远停在 15% 和 0%。

### 3.3 六类信息陷阱与处理策略

这 26 条数据里包含了典型的"多来源信息问题"，看起来是题目刻意埋的测试点：

| 陷阱类型 | 数据实例 | 产品处理 |
| --- | --- | --- |
| **同一活动重复/增量发布** | 01 ↔ 09（训练营场地与首次时间变更）、03 ↔ 20（开发名额已满，改补设计/材料） | 活动库以「活动」为单位；补充通知**不独立成条**，合并为父活动的**变更记录**，详情页显示"最近更新" |
| **时效已过** | 04（直播 9/18 已结束，回放待上传）、19（报名 9/18 已截止，仅可候补）、17（网盘链接 9/22 失效） | 状态机自动标注"已结束 / 报名已截止 / 链接可能失效"；列表默认过滤；"待回放"作为独立状态 |
| **信息不完整** | 12（费用未提供）、16（截止未注明）、22/23（地点未定）、24/25（无主办方无地点） | 显示**信息完整度**并逐项标"未注明"；完整度过低触发警示 |
| **疑似营销/风险** | 24（"零门槛、日结"，要求加私人微信，无主办方）、25（标题为技术交流，正文是商家购买链接） | 风险标记；高风险条目不予收录或强制警示；禁止站外私聊引流 |
| **无需报名 / 非先到先得** | 02、04、10、15、21、26（无需报名，共 6 条）；14（报名表≠录取）；07（意向登记≠最终提交） | 报名方式支持"无需报名·直接到场"；"需审核"必须显式提示，避免学生误以为报了就能去 |
| **非活动类信息** | 17（Python 资料合集，长期开放） | 增加"资料/机会"类型，不套用"活动时间/地点/报名"字段 |

### 3.4 由此确定的产品约束

1. 发布必须挂靠活动库条目（对应"只有汇总内活动可发布"）。
2. 活动库条目必须**结构化**（要求、地点、时间、截止、名额、费用、收获、发布方、风险等级）。
3. 必须支持**父活动 + 变更记录**两层结构，否则 09、20 会作为独立活动污染列表。
4. 必须同时支持**六种状态**：报名中 / 即将开始 / 报名已截止 / 已结束（含待回放）/ 长期有效 / 地点待定。
5. 必须支持**非活动类**（资料）类型。

## 4. 核心机制一：白名单挂靠式发布

### 4.1 发布流程

```
1. 认证            校园邮箱 / 学号（未认证不可发布）
2. 选定活动        ← 只能从活动库搜索并选定，不能自由创建标题
3. 展示平台标注     系统自动填充「要求 + 地点」等字段，发布者不可删除，只能追加补充说明
4. 上传活动资料     PPT / Word / 图片 / txt / md → 异步转换 → 在线预览
5. 提交            学院·官方·认证组织直发；学生个人前 2 条送审
6. 生成详情页      资料预览区 + 平台标注块
```

### 4.2 匹配与别名（针对 01↔09 问题）

发布者输入"程序设计训练营"时，候选列表返回：

```
程序设计训练营                    [正式条目 01]
  └ 程序设计训练营 · 补充通知      [更新 09 → 将合并展示]
```

- 支持**别名**：如「程序设计训练营」→ 01、「AI 挑战赛」→ 07/15。
- 选定正式条目后，其下所有补充通知自动作为**变更记录**挂载，用户只会看到**一个**活动，以及"最近更新：首次训练改为 9/21 19:30，地点改至实验楼 A402"。

### 4.3 主体分级与发布权限

| 主体类型 | 认证方式 | 发布策略 | 标识 |
| --- | --- | --- | --- |
| 学院 / 校方 | 官方域名邮箱 + 后台开通 | 直发 + 抽检 | 学院 ✓ |
| 注册社团 / 学生组织 | 负责人认证 + 指导单位确认 | 直发 + 抽检 | 认证组织 ✓ |
| 在校学生个人 | 学号 / 校园邮箱认证 | 前 2 条人工审核，之后直发 + 抽检 | 个人（未认证） |
| 高风险命中 | 自动规则 + 人工复核 | 不予收录或强制警示 | 风险提示 |

> 数据集中 24、25 两条正是"学生个人发布"的反面样本，说明个人发布必须叠加**风险规则**：命中"加私人微信""日结""购买链接""零门槛"等关键词即转人工。

### 4.4 申请收录（可选，需决策）

严格按"只有汇总内活动可发布"执行，会导致平台**永久固化**：数据集中 22、23 是学生自发活动，若不允许新活动进入，原需求中"学生自主发布活动"就彻底无法实现。

**建议保留一个受控入口**：白名单外的新活动不能直接发布，但可提交「申请收录」，管理员审核通过后入活动库，之后才能发布。这样既保持"默认拒绝"的守门效果，又不切断学生自主发布。**此项需确认是否采用（见第 17 章问题 1）。**

## 5. 核心机制二：要求与地点标注

这是本次评审提出的机制，也是"帮助学生判断"的主要载体。

### 5.1 字段拆解方案

原文是散文，需要拆成结构化字段。**26 条数据量小，建议一次性人工拆解录入，而不是写 NLP 抽取规则**——人工准确率 100%，成本约半天；规则抽取在这种写法多变的散文上准确率难以保证，且"9月22日18:00截止"这类无年份日期会产生跨年歧义。

拆解产物已生成：同目录 `activities.seed.json`。字段定义：

| 字段 | 说明 | 数据实例 |
| --- | --- | --- |
| `audience` | 面向人群 | 全校学生 / 大一新生 / 仅限大二及以上 |
| `threshold` | 参与门槛 | 零基础可参加 / 需提交自我介绍 / 需组队 |
| `commitment` | 投入要求 | 每周≥4小时 / 共 6 周 / 90 分钟 |
| `requirement` | **综合要求**（由上面三项合成，供标注块直接展示） | 见 5.2 |
| `location` | 地点 | 实验楼 A402 / 明德楼 B203 |
| `location_status` | 地点状态（枚举） | 明确 / 线上 / 待确认 / 未注明 |
| `schedule` | 时间 | 9月21日 19:00—20:30 |
| `deadline` | 报名截止 | 9月24日 22:00 |
| `deadline_status` | 报名截止状态（枚举） | 明确 / 已截止 / 长期 / 未注明 / 无需报名 / 继承父活动 |
| `quota` | 名额 | 限 30 人 / 座位有限 |
| `cost` | 费用 | AA / 未提供 |
| `outcome` | 收获 | **全部为 null（原文 0 条提及）** |
| `signup_mode` | 报名方式（枚举） | 无需报名 / 站内报名 / 需登记 / 需审核 / 站内组队 / 外链 / 站外私聊 / 候补 / 未注明 |

### 5.2 标注块：长什么样

按评审意见，标注块放在**文件下方**：

```
┌ 📎 活动资料（发布者提供，平台未逐份核验）────────┐
│  招新宣讲.pptx    24 页   [在线预览] [下载]       │
│  报名须知.docx     2 页   [在线预览] [下载]       │
│  场地示意.png              [查看大图]             │
└──────────────────────────────────────────────────┘

┌ 📌 要求与地点 ── 来源：平台活动库（可信基准）────┐
│                                                   │
│  要求   面向全校学生 · 零基础可参加                │
│         每周六 19:00 训练，需持续参与              │
│         需在 9月24日 22:00 前报名                  │
│                                                   │
│  地点   实验楼 A402                                │
│         ⚠ 曾变更：首次训练改为 9月21日 19:30       │
│         [地图导航 · 步行 8 分钟]                   │
│                                                   │
│  未注明  名额 · 费用 · 收获（学分/工时/证书）       │
│  信息完整度  ●●○○○  2/5                          │
└──────────────────────────────────────────────────┘
```

三个设计要点：

1. **来源标注是必须的**：标注块明确写"来源：平台活动库"，附件区明确写"发布者提供，平台未逐份核验"。这样即使发布者资料有误，学生仍知道以哪一份为准。这是本机制可信度的基础。
2. **"未注明"行不能省**：这是与"留空"完全不同的信息。学生看到"收获未注明"会去问，看到空白会以为没有。
3. **页面顶部仍要有摘要**：标注在文件下方意味着需要滚动。为解决新生"看不到"的问题，"要求 / 地点 / 截止"三项关键结论同时出现在页首决策卡中，标注块作为完整版。**这不是违背评审意见，而是同一份数据的第二次呈现。**

### 5.3 信息完整度评分

按 5 个关键项计分：**时间、地点、报名截止、名额、费用**。

- 5/5：正常展示
- 2–4/5：展示完整度进度点 + 缺失项列出
- 0–1/5：**强制警示**（如 24、25 两条信息几乎全缺，本身就应触发风险审核）

完整度同时用于**排序降权**：同等条件下，信息完整的活动排前面。这比人工审核更能持续驱动组织者补齐信息。

### 5.4 高风险条目的处理

数据集中 24（"零门槛、日结"+加私人微信+无主办方无地点）与 25（标题技术交流、实为商家购买链接）应作为**反例基线**：

| 命中特征 | 处置 |
| --- | --- |
| 要求添加私人微信/QQ 获取详情 | 不予收录（站外引流，无法追溯） |
| 承诺"零门槛、日结""轻松赚钱" | 转人工审核 + 若收录则强制加警示条 |
| 标题与实际内容不符（标题技术交流、正文卖货） | 标记"疑似商业推广"，展示时降权 |
| 无主办方且无地点 | 不予收录 |
| 含购买链接/优惠码 | 标记商业推广，限流展示 |

**产品原则：宁可少收录，不可让学生白跑一趟或被引流到站外。**

## 6. 核心机制三：更新合并与时效管理

### 6.1 更新合并

活动库为两层结构：**活动（父）** + **变更记录（子）**。

| 父活动 | 变更记录 | 变更内容 |
| --- | --- | --- |
| 01 蓝桥杯训练营 | 09 补充通知 | 首次训练：9/20 → **9/21 19:30**；地点：未注明 → **实验楼 A402**；报名截止不变 |
| 03 创新创业团队招募 | 20 补充说明 | 招募方向：开发/设计/材料 → **开发已满，仅补设计/材料**；截止不变 |

详情页展示：`最近更新 9月19日 · 首次训练时间与地点调整`（可展开查看变更前后对比）。

**这是"多来源信息问题"最直接的解法**：不消除重复信息，而是把它归并成一条可追溯的信息流。

### 6.2 时效状态机

```
报名中 ──截止时间过──> 报名已截止 ──可候补──> 候补中
   │
   └──活动结束──> 已结束 ──有回放──> 已结束（回放可看）

长期有效（无截止）──> 长期展示，不自动过期
地点待定 ──地点确认──> 报名中
```

| 状态 | 数据实例 | 列表表现 | 详情页表现 |
| --- | --- | --- | --- |
| 报名中 | 01、03、05 | 正常 | 报名按钮可用 |
| 报名已截止（可候补） | 19 | 默认过滤 | 顶部灰条"报名已于 9/18 截止，现场有余位可候补" |
| 已结束 · 待回放 | 04 | 默认过滤 | 灰条"直播已结束，预计 9/20 上传回放"，提供订阅提醒 |
| 长期有效 | 08、16 | 正常（标注"长期"） | 无截止倒计时 |
| 链接可能失效 | 17 | 正常 | 警示"网盘提取信息有效至 9/22" |
| 地点待定 | 22、23 | 正常但降权 | 地点处显示"待确认"，可订阅地点确认通知 |

## 7. 附件在线浏览

需求明确要求支持 PPT、Word、图片、txt、md。**不能要求用户下载 30 页 PPT 才能判断**，因此设计转换流水线：

| 格式 | 预览方案 | 兜底 |
| --- | --- | --- |
| `.pptx` / `.ppt` | LibreOffice 无头转 PDF → PDF.js 逐页渲染；先生成前 5 页给首屏，其余按需转 | 转换失败则提供原件下载 |
| `.docx` / `.doc` | 转 PDF 渲染（版式保真） | 同上 |
| `.png` / `.jpg` / `.webp` / `.gif` | 直接渲染 + 多尺寸缩略图 | — |
| `.txt` | **编码探测**（UTF-8 / GBK）后纯文本渲染 | 探测失败按 UTF-8 强解 |
| `.md` | markdown-it 渲染 + 代码高亮 + 外链图片代理 | — |

**流水线**：上传 → 原件存对象存储 → 入队 → 转换 Worker → 产物入库 → 状态回写。
状态机：`pending → processing → ready / failed`，前端显示"正在生成预览"，不阻塞发布。

**两个易踩的坑**：
- 中文 txt 大量为 GBK，按 UTF-8 读会乱码，**必须做编码探测**。
- 转换是 CPU 密集型且要跑他人文档，**必须独立容器、禁外网、限时限额**。

**安全约束（P0 即需落地）**：扩展名白名单 + magic number 双校验、拒绝宏格式（`.docm`/`.pptm`/`.xlsm`）、单文件 ≤50MB、单活动 ≤10 个附件、ClamAV 扫描。

## 8. 一页看懂（页首决策卡）

页首固定一张卡，与第 5 章标注块同源，但只放最关键的结论：

```
⚡ 一页看懂
收获   未收录（原文未提及学分/工时/证书）
时长   每周六 19:00，持续性训练
门槛   面向全校学生 · 零基础可参加
截止   9月24日 22:00
地点   实验楼 A402（曾变更）· [导航]
完整度 ●●○○○ 2/5   未注明：名额 · 费用 · 收获
最近更新 9月19日 · 训练时间与地点调整
```

- "收获"行如实显示"未收录"，**不编造、不留空**。
- 冲突检测分阶段：P1 只检测"与本平台已报名/已收藏活动"的时间冲突；P2 支持导入 `.ics` 课表（比对接教务系统耦合低得多）。
- 往届口碑来自**实际有报名记录**的用户，否则刷分无成本；无评价则显示"暂无往届评价"并降权。

## 9. 发现与检索

- **筛选**：时间（今天/本周/本周末/自定义）、类型、收获标签、门槛（零基础/需基础）、面向人群、报名状态、信息完整度。
- **排序**：综合 = 报名截止紧迫度 + 主体信誉 + **信息完整度** + 新鲜度；另可选"最新发布""即将截止"。
- **检索**：标题 + 别名 + 要求 + 地点 + 附件抽取文本。
- **列表卡片**直接显示判断要素（门槛、截止、地点、主体徽章、完整度），避免"点进去才发现不合适"。
- **默认排除**已结束与报名已截止条目（可通过筛选查看）。

## 10. 参与、报名与招募伙伴

### 10.1 报名方式必须匹配数据现实

`signup_mode` 枚举在 26 条数据中的实际分布为：**无需报名 6 条**、站内报名 7 条、需登记 1 条、需审核 1 条、站内组队 2 条、外链 2 条、站外私聊 1 条、候补 1 条、未注明 3 条（另 2 条为变更记录，无报名方式）。因此报名模块**不能只有"立即报名"一个按钮**：

| 报名方式（枚举值） | 数据实例 | 按钮表现 |
| --- | --- | --- |
| 无需报名 | 02、04、10、15、21、26 | "无需报名，直接前往" + 加入日历（15 为提交作品即可，无报名环节） |
| 站内报名 | 01、03、05、06、08、13、16 | "立即报名"（06 为满员即止，不显示倒计时） |
| 需登记 | 07 | "完成意向登记（≠作品提交）" |
| 需审核 | 14 | "提交报名表（需审核，报名≠录取）"——文案必须说清 |
| 站内组队 | 22、23 | "发起/加入组队" |
| 外链 | 17、25 | 跳转并记录"报名意图"（25 为商业推广，见 5.4） |
| 站外私聊 | 24 | **不提供跳转**，标记高风险 |
| 候补 | 19 | "已截止，加入候补通知" |
| 未注明 | 11、12、18 | 显示"报名方式未注明，建议向主办方确认" |

### 10.2 招募伙伴（对应 22、23 与学生自发需求）

- **只允许基于活动/机会组队，不开放独立社交广场**。
- 队长设人数上限、可见范围（全站/仅同院系）、是否需批准。
- 成员展示：昵称 + 院系 + 年级，**不展示学号、手机号、微信**。
- 联系仅站内私信；提供屏蔽与举报。
- 22、23 属于"学生自发活动"，若未获活动库收录，则**只能在招募板块内以"个人发起·未认证"形式存在**，且强制显示"地点待确认/时间未定"。

## 11. 新生引导

- **首次进入三步引导**：选院系与年级 → 选 3 个兴趣标签 → 生成个性化发现流（避免空列表）。
- **新生专区**：聚合"零门槛 + 无需组队 + 无需报名 + 时间短 + 地点明确"的活动，如 02、10、21。
  - **注意**：由于地点明确的活动仅 4 条，专区条件若强求"地点明确"会导致内容过少。**建议地点作为加权项而非硬过滤。**
- **地点要说人话**：不只写"三教 305"，同时给"从 XX 宿舍步行 8 分钟" + 地图跳转。
- **校园节奏提示**：开学季/期中/期末常见机会类型的轻量提示，弥补"不知道有什么可参加"的信息差。

      ├──── n Team
      ├──── n Review

## 15. 技术选型与路线图

### 15.1 技术选型

| 层 | 建议 | 理由 |
| --- | --- | --- |
| 前端 | Next.js + TypeScript + Tailwind | SSR 让详情页可分享、可被收录（学生常从微信打开链接） |
| 后端 | NestJS（或 MVP 用 Next.js API Routes） | 审核与权限逻辑会快速变复杂 |
| 数据库 | PostgreSQL + Prisma | 关系清晰；外键约束可强制白名单；`pg_trgm` 支撑中文模糊检索 |
| 对象存储 | S3 兼容（本地 MinIO） | 原件与转换产物都需存储并可签名访问 |
| 队列 | Redis + BullMQ | 转换必须异步，否则上传接口超时 |
| 转换服务 | 独立容器 + LibreOffice 无头 + ClamAV | 隔离不可信文档，禁外网，限时限额 |
| 预览 | PDF.js / react-pdf | 免商业授权，逐页渲染对大 PPT 友好 |
| 部署 | Docker Compose（校内服务器） | 数据不出校、成本可控 |

### 15.2 路线图

| 阶段 | 范围 | 目标 |
| --- | --- | --- |
| **P0**（2–3 周） | 26 条条目结构化入库 → 挂靠式发布 → 附件转换与在线预览 → **要求与地点标注块** → 列表/筛选/详情 → 我的发布 | 跑通"选定活动 → 发布 → 学生看懂要求与地点"闭环 |

## 16. 非功能需求、指标与风险

### 16.1 非功能需求

**安全**：上传白名单 + magic number 校验、拒宏格式、ClamAV、转换隔离；RBAC + 资源级所有权校验；附件走签名临时 URL。
**性能**：列表 P95 < 300ms；详情首屏 < 1.5s；预览首屏 < 1.5s（大文件先出前几页）。
**隐私**：学号仅后台可见；联系方式默认不公开，仅站内私信；组队信息最小化；提供注销与数据导出。
**可访问性**：移动端优先、单手可达；对比度符合 WCAG AA；状态不只用颜色区分。

### 16.2 指标体系

| 类别 | 指标 |
| --- | --- |
| 北极星 | 每周有效参与数（站内报名或外链点击后 7 天内确认参与） |
| **信息质量（本版新增重点）** | **地点覆盖率**（当前 15%）、**收获覆盖率**（当前 0%）、平均信息完整度、风险条目处置时效 |
| 新生体验 | 引导完成率、首周人均浏览活动数、首周报名转化率、新生专区点击率 |
| 治理 | 过期活动归档及时率、重复条目合并率、举报率、审核通过率 |
| 功能健康度 | 附件预览成功率与首屏耗时、转换失败率 |

### 16.3 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **白名单数据陈旧** | 新活动无法进入，平台脱离现实 | 申请收录入口（4.4）+ 定期同步官方通知 |
| **地点信息大面积缺失** | 标注块大量显示"未注明"，学生仍找不到地方 | 发布者补录 + 平台审核；把"地点明确"作为激励（完整度高则排序靠前） |
| **收获信息全缺** | 决策卡无法回答"值不值得" | 显式标注"未收录" + 开放组织者补充；不编造 |
| 审核人力不足 | 低质信息回流 | 主体分级 + 自动风险规则 + 抽检，而非全量人工 |
| 手动结构化成本 | 条目增多后不可持续 | 先人工录入小样本（26 条），再视规模引入半自动抽取 + 人工校对 |
| 转换服务资源开销 | 上传卡顿、成本高 | 异步队列 + 限流 + 大文件只转前几页 |
| 上传资料版权与敏感内容 | 法律风险 | 上传即声明权属与授权；侵权投诉下架通道 |

## 17. 待决策问题

1. **白名单是封闭还是开放"申请收录"？**（严格按"只有汇总内活动可发布"会永久切断学生自主发布，与原需求冲突；建议保留受控入口）
2. **地点信息如何补齐？** 26 条中仅 4 条有地点。是要求发布者补充、由运营二次采集，还是对接场地/教务系统？
3. **"收获"字段 0 条，决策卡的这一行如何呈现？** 建议显式"未收录"并开放组织者补充，而非留空或省略。
4. **24、25 类条目处置口径？** 不予收录 / 收录但强制警示 / 仅限管理后台可见。
5. **原文日期无年份**（如"9月21日"），跨年如何判断？建议所有条目统一附加学期标识（如 2026 秋季学期）。
6. **是否需要落地代码？** 若需要，建议从 P0 的"结构化种子数据 + 标注块 + 附件转换"三件事做起，其中附件转换是最高技术风险项。
